**Learnings for future iterations:**
- UI polish is best implemented progressively throughout development rather than as a separate final step
- Automated tests can verify styling by checking CSS class application (structure tests, not visual tests)
- jsdom environment doesn't compute CSS styles, so test class application rather than computed styles
- CSS patterns used in this project:
  - Dark theme with rgba colors for transparency effects
  - Flexbox for header layouts (space-between for left/right positioning)
  - CSS Grid for equal-width split panes (grid-template-columns: 1fr 1fr)
  - Consistent spacing with rem units (0.5rem, 1rem, 1.5rem)
  - Color coding for status indicators (green=connected, yellow=connecting, red=disconnected/error)
  - Serif fonts for reading (preview), monospace for code (editor)
- Testing pattern: verify component renders with expected CSS classes, not visual appearance
- **PATTERN**: Progressive styling throughout development yields better UX than "polish at the end" approach
