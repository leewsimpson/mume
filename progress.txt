## Codebase Patterns
- Comments are stored as YAML files in `.mume/` folder in GitHub repos, not in a database
- Comment replies use a flat array within comments (no separate parent_id), preventing nested replies by architecture
- Frontend uses 10-second polling for comment updates (no WebSocket for comments)
- Backend API requires `documentPath`, `repoOwner`, `repoName` for all comment operations
- E2E tests use Playwright with mocked GitHub API responses in `tests/e2e/mocks/github-api.mock.ts`
- Comment sidebar has overlay backdrop that can intercept clicks - use close button instead of toggle for closing

### Learnings for future iterations
- The comment system architecture uses flat arrays for replies (no nested parent_id) - this is intentional to prevent deep nesting
- Comment sidebar has an overlay backdrop (`comment-sidebar-backdrop`) that intercepts clicks on elements behind it
- E2E mocks in `github-api.mock.ts` work differently than real backend - mocks search all comments by ID, backend requires path/repo info
- When testing sidebar toggle, use the close button inside sidebar instead of the toggle button
- **Testing:** When testing API routes that use `passport` and `redis`, it's critical to mock `server.js` exports and use `unstable_mockModule` for ESM modules to avoid starting the real server and connecting to Redis during unit/integration tests.
